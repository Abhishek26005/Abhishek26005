**Problem:** Usable surplus food may go to waste while nearby communities and organizations need support. A coordinated workflow can help donors, NGOs, and delivery partners manage distribution.

```text
Donor
  |
  v
Donation details and availability
  |
  v
NGO review / coordination

Delivery partner or self-pickup

Collection and completion status
```

**Potential improvements**

### AI Bug Analyzer — Programming Error Assistant

**Goal:** Provide a focused interface where a developer can submit an error message or code snippet and receive an AI-generated explanation with a possible fix.

**Main user journey**
1. Enter an error message or relevant code.
2. Validate that the input is not empty.
3. Send the request to a protected backend endpoint.
4. Receive a structured response.
5. Display the likely cause and suggested solution.
6. Allow the user to copy the suggestion.
7. Save history when authentication and storage are configured.
8. Show useful loading, success, and failure states.

Illustrative response shape:

```json
{
  "summary": "Short description of the likely issue",
  "cause": "Why the issue may be happening",
  "solution": "Suggested steps or corrected example",
  "explanation": "How the suggested change addresses the issue"
}
```

This is an example response shape, not a guarantee that every error can be diagnosed correctly.

**Engineering considerations**
- Keep AI provider API keys on the server.
- Validate and limit request size.
- Treat submitted code as untrusted input.
- Communicate uncertainty when a diagnosis is not definitive.
- Handle provider failures and rate limits.
- Never execute arbitrary submitted code on the server.
- Avoid storing secrets or unnecessary personal data in history.
- Test empty, malformed, and oversized requests.

## 🎨 UI/UX Principles

### Visual hierarchy
- Use headings that explain each section.
- Keep primary actions easy to identify.
- Use spacing to group related content.
- Avoid decoration that competes with important information.
- Keep typography readable across devices.

### Interaction design
- Provide visible feedback after important actions.
- Prevent accidental destructive actions.
- Keep forms focused and predictable.
- Preserve useful user input when an operation fails.
- Make loading and disabled states clear.

### Accessibility
- Use semantic HTML where applicable.
- Provide meaningful alternative text for images.
- Maintain readable contrast.
- Do not rely on color alone to communicate status.
- Ensure keyboard navigation works for web interfaces.
- Respect text scaling and touch-target needs on mobile.

### Responsive design
- Design for narrow screens when the main use case is mobile.
- Avoid fixed widths that cause horizontal overflow.
- Check layouts at multiple viewport sizes.
- Keep long content readable.
- Make tables and code blocks manageable on small screens.

## 🏗️ Development Workflow

```text
Understand the problem
        |
        v
Define requirements and user flows
        |
        v
Plan components, data, and API contracts
        |
        v
Implement a small working increment
        |
        v
Test expected and edge-case behavior
        |
        v
Review security, accessibility, and errors
        |
        v
Document setup and usage
        |
        v
Deploy, observe, and improve
```

### Before coding
- Clarify the problem and expected outcome.
- Identify the main user roles.
- Write down critical workflows.
- Decide what data needs to be stored.
- Identify failure cases and permissions.
- Sketch the screen hierarchy or API contract.

### While coding
- Use descriptive names.
- Keep functions and components focused.
- Avoid duplicating logic unnecessarily.
- Validate data at the correct boundary.
- Keep secrets in environment variables.
- Commit work in small, understandable changes.

### Before publishing
- Run available tests.
- Check the production build.
- Verify environment configuration.
- Remove credentials and private files.
- Update setup instructions.
- Add screenshots only when they contain no private data.
- Check links and repository visibility settings.

## 🧑‍🔧 Debugging Approach

1. Reproduce the problem consistently.
2. Read the complete error message and stack trace.
3. Identify the first relevant application frame.
4. Check assumptions about input and state.
5. Reduce the problem to the smallest useful example.
6. Inspect recent changes and configuration.
7. Test one hypothesis at a time.
8. Verify the fix against the original failing case.
9. Check related edge cases.
10. Record the cause and solution when useful.

## 📖 Engineering Glossary

| Term | Meaning |
| --- | --- |
| API | An interface that lets software components exchange requests and responses. |
| Authentication | Verifying who a user or service is. |
| Authorization | Deciding what an authenticated user or service may access. |
| Component | A reusable UI building block with a focused responsibility. |
| CRUD | Create, read, update, and delete operations for stored data. |
| DTO | A data transfer object that defines data moving between application layers. |
| Environment variable | Configuration supplied outside application source code. |
| Exception handling | Responding to exceptional conditions without uncontrolled failure. |
| Foreign key | A relational database constraint linking a row to another table. |
| HTTP status code | A response indicator describing the outcome of an HTTP request. |
| Index | A database structure that can improve selected query patterns. |
| Integration test | A test that checks how multiple components work together. |
| JWT | A token format commonly used to carry claims between systems. |
| Migration | A controlled change to a database schema or data structure. |
| Normalization | Relational design practices that reduce unwanted duplication. |
| Pagination | Returning a large result set in smaller pages. |
| Props | Inputs passed from a parent component to a React component. |
| REST | An architectural style commonly used to design HTTP APIs around resources. |
| State | Data that can change over time and influence what a UI renders. |
| Unit test | A test that checks a small unit of behavior in isolation. |
| Validation | Checking that data satisfies expected rules before acceptance. |
| Version control | Tracking changes to files over time. |

## 🛠️ Troubleshooting Notes

### Application will not start
- Read the full terminal output.
- Confirm the required runtime is installed.
- Check dependency installation.
- Verify environment variables.
- Confirm the configured port is available.
- Reproduce the issue with a clean start.

### API request fails
- Confirm the URL and HTTP method.
- Check request headers and body.
- Verify authentication state.
- Inspect the response status and body.
- Check server logs without exposing secrets.
- Test the endpoint independently when possible.

### Database connection fails
- Verify host, port, database name, and credentials.
- Confirm the database service is running.
- Check network and firewall rules.
- Review access permissions.
- Avoid printing passwords in debug output.
- Test with a development database.

### UI layout breaks
- Reproduce at the affected viewport size.
- Inspect overflowing elements.
- Check fixed widths and long text.
- Verify flex and grid constraints.
- Test with larger text settings.
- Check browser console warnings.
